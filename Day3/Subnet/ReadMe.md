# 네트워크 기초 & 서브네팅 및 라우팅 실습 정리

네트워크 기초 개념인 서브네팅, AND 연산, DTE/DCE, 그리고 정적 및 동적 라우팅(RIP)에 대한 실습 및 이론 정리 문서입니다.

---

## 1. 서브넷 마스크 및 IP 네트워크 분할 (Subnetting)

### 1.1 `/24`와 `/25` 서브넷 마스크 비교 실습
PC0과 PC1의 서브넷 마스크를 `255.255.255.0`(/24)에서 `255.255.255.128`(/25)로 변경할 경우 통신 변화:

* **`/24` 환경 (`255.255.255.0`)**:  
  IP 범위가 `192.168.16.0 ~ 192.168.16.255`로 동일한 네트워크 영역에 존재하여 통신 가능.
* **`/25` 환경 (`255.255.255.128`)**:  
  경계선(`.128`)을 기준으로 2개의 서브넷 영역으로 분할되어 통신 불가 (`Request timed out`).

---

### 1.2 AND 연산을 통한 네트워크 주소 계산

네트워크 장비는 IP 주소와 서브넷 마스크의 비트 단위 AND 연산을 통해 동일 네트워크 여부를 판단합니다.

#### 1) PC0 (192.168.16.100 /25)
  IP 주소 : 11000000 . 10101000 . 00010000 . [0]1100100 (192.168.16.100)
  마 스 크 : 11111111 . 11111111 . 11111111 . [1]0000000 (255.255.255.128)
-------------------------------------------------------------------------
  AND 연산 : 11000000 . 10101000 . 00010000 . [0]0000000 
  => 네트워크 주소 : 192.168.16.0 (1구역 범위: .0 ~ .127)

#### 2) PC1 (192.168.16.200 /25)
  IP 주소 : 11000000 . 10101000 . 00010000 . [1]1001000 (192.168.16.200)
  마 스 크 : 11111111 . 11111111 . 11111111 . [1]0000000 (255.255.255.128)
-------------------------------------------------------------------------
  AND 연산 : 11000000 . 10101000 . 00010000 . [1]0000000 
  => 네트워크 주소 : 192.168.16.128 (2구역 범위: .128 ~ .255)

> **결과**: PC0과 PC1은 계산된 네트워크 주소가 다르므로 서로 다른 네트워크로 분류됩니다.

### 1.3 서브네팅 공식 & 예제

* **Network ID**: 서브넷 마스크의 `1` 부분
* **Host ID**: 서브넷 마스크의 `0` 부분
* **빌린 비트 수 (n)**: Host ID 자리에서 Network ID로 빌려온 `1`의 개수
* **생성되는 서브넷 수**: 2^n
* **실제 할당 가능한 IP 수**: 전체 IP 개수 - 2 *(네트워크 주소 및 브로드캐스트 주소 제외)*

#### 예제: 7개 부서에 IP 할당하기
* **조건**: 기업 내 7개 부서에 맞게 서브넷 분할
* **필요한 서브넷 수**: 2^3 = 8개 (n=3 비트 대여)
* **서브넷 마스크**: `11111111.11111111.11111111.11100000` (`255.255.255.224` / `/27`)
* **서브넷별 IP 범위 & 할당 가능 IP**:

| 서브넷 번호 | 전체 IP 범위 | 네트워크 주소 | 브로드캐스트 주소 | **실제 할당 가능 IP 범위** |
| :---: | :---: | :---: | :---: | :--- |
| #1 | 0 ~ 31 | 192.168.16.0 | 192.168.16.31 | **192.168.16.1 ~ 192.168.16.30** |
| #2 | 32 ~ 63 | 192.168.16.32 | 192.168.16.63 | **192.168.16.33 ~ 192.168.16.62** |
| #3 | 64 ~ 95 | 192.168.16.64 | 192.168.16.95 | **192.168.16.65 ~ 192.168.16.94** |
| #4 | 96 ~ 127 | 192.168.16.96 | 192.168.16.127 | **192.168.16.97 ~ 192.168.16.126** |
| #5 | 128 ~ 159 | 192.168.16.128 | 192.168.16.159 | **192.168.16.129 ~ 192.168.16.158** |
| #6 | 160 ~ 191 | 192.168.16.160 | 192.168.16.191 | **192.168.16.161 ~ 192.168.16.190** |
| #7 | 192 ~ 223 | 192.168.16.192 | 192.168.16.223 | **192.168.16.193 ~ 192.168.16.222** |
| #8 | 224 ~ 255 | 192.168.16.224 | 192.168.16.255 | **192.168.16.225 ~ 192.168.16.254** |

## 2. 장비 연결 인터페이스 (DTE / DCE)

* **DTE (Data Terminal Equipment)**: 데이터 단말기 (예: 라우터, PC)
* **DCE (Data Circuit-terminating Equipment)**: 신호 변환기 및 통신 중계기 (클럭 신호 제공, 예: 모뎀, CSU/DSU)

### Packet Tracer 실습
1. Router0, Router1의 전원을 끄고 `HWIC-2T` 모듈 장착 후 전원 ON.
2. Connections에서 **Serial 연결 (`Se0/3/0`)** 진행 (DCE 측에 클럭 레이트 설정).
3. `config-if` 모드에서 각 라우터 인터페이스에 IP 부여.
4. 라우터 간 핑 테스트 성공 확인 (`Router0` ↔ `Router1`).

## 3. 라우팅 (Routing)

서로 다른 네트워크 간 패킷을 전송하기 위해 경로를 설정하는 과정입니다.

### 3.1 정적 라우팅 (Static Routing)
관리자가 직접 목적지 경로를 지정하는 방식.

# 명령어 형식
ip route [목적지 네트워크 주소] [서브넷 마스크] [Next-Hop IP (경유지 IP)]

# 예시
Router(config)# ip route 192.168.20.0 255.255.255.0 192.168.24.200

* `show ip route` 실행 시 라우팅 테이블에 `S` (Static)로 표시됨.
* AD(Administrative Distance) 값: `1` (신뢰도가 매우 높음).

---

### 3.2 동적 라우팅 (Dynamic Routing) - RIP Protocol
라우터끼리 라우팅 정보를 서로 주고받아 자동으로 경로를 업데이트하는 방식.

#### 라우팅 프로토콜 주요 비교
| 프로토콜 | 종류 | 최적 경로 기준 (Metric) | 최대 홉 수 (Max Hop) |
| :--- | :--- | :--- | :--- |
| **RIP** | 거리 벡터 (Distance Vector) | 홉 수 (Hop Count) | **15 Hops** (16부터 도달 불가) |
| **EIGRP** | 고급 거리 벡터 | 대역폭, 지연, 신뢰성, 부하 등 | 255 Hops |
| **OSPF** | 링크 상태 (Link State) | 대역폭 (Cost) | 제한 없음 |

#### RIP 설정 방법
Router(config)# router rip
Router(config-router)# network [직접 연결된 네트워크 주소]

#### RIP 주요 개념 및 동작 타이머
* **AD 값**: `120` (`[120/1]`의 형태에서 앞 숫자가 AD, 뒤 숫자가 Metric/Hop 수).
* **한계**: 회선 속도나 인터페이스 성능을 고려하지 않고 라우터 개수(Hop)로만 경로 산정.
* **타이머 (RIP v1 기준)**:
  1. **Update Timer (30초)**: 30초마다 라우팅 정보 업데이트 패킷 전송.
  2. **Invalid Timer (180초)**: 180초 동안 업데이트가 없으면 해당 경로를 무효(Invalid) 처리.
  3. **Hold-down Timer (180초)**: 더 나쁜 조건의 경로 정보를 일정 시간 동안 수신 거부.
  4. **Flush Timer (240초)**: 최종적으로 정보가 없으면 라우팅 테이블에서 삭제.

---

### 3.3 RIP v1 vs RIP v2 주요 차이점
| 구분 | RIP Version 1 | RIP Version 2 |
| :--- | :--- | :--- |
| **타입** | Classful (서브넷 마스크 미전송) | Classless (서브넷 마스크 전송) |
| **자동 축약 (Auto-Summary)** | 기본 적용 (비활성화 불가) | 기본 적용 (`no auto-summary`로 비활성화 가능) |
| **호환성** | v1, v2 패킷 모두 수신 가능 | v2 패킷만 수신 가능 |

> **주의사항**: RIP v1과 RIP v2가 혼재되어 있을 경우 버전 호환성 문제로 라우팅 정보 공유가 정상 동작하지 않을 수 있습니다.

* `show ip protocols`: 현재 동작 중인 라우팅 프로토콜 설정 정보 확인
