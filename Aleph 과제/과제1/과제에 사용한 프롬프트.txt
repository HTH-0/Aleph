이 페이지의 목적은 일반적인 이력서 양식을 복제하는 것이 아니다.

**링크 하나로 나의 장점, 공부 방식, 문제를 해결하는 방식과 실제 경험을 보여주는 개인 포트폴리오 페이지**를 만드는 것이 목적이다.

중요한 것은 화려한 디자인보다 **내가 실제로 어떤 상황에서 무엇을 했고, 그 결과 무엇이 달라졌는지를 다른 사람이 한눈에 이해할 수 있도록 표현하는 것**이다.

---

## 1. 가장 중요한 작성 원칙

아래에 제공하는 내용에서 벗어나서 사실을 만들어내지 마.

- 존재하지 않는 경력, 프로젝트, 회사, 기관명, 자격증을 추가하지 않는다.
- 내가 제공하지 않은 숫자나 성과를 임의로 만들지 않는다.
- 경험을 더 있어 보이게 과장하지 않는다.
- 문장을 자연스럽고 전문적으로 다듬는 것은 가능하지만, 사실관계는 변경하지 않는다.
- "전문가", "최고", "뛰어난", "탁월한" 같은 근거 없는 자기평가는 최대한 사용하지 않는다.
- 나의 경험에서 드러나는 강점을 스스로 분석해서 적절한 제목과 설명으로 정리한다.
- AI를 사용해서 학습했다는 점도 숨기지 않고 자연스럽게 표현한다.

이 포트폴리오는 **스스로를 과장해서 보여주는 페이지가 아니라, 실제 행동과 결과를 통해 나를 보여주는 페이지**여야 한다.

---

## 2. 내가 전달하고 싶은 핵심 경험

### 경험 1 — 새로운 분야를 배우고 부족한 부분을 보완한 경험

상황:
학원에서 네트워크 분야를 처음 접했다.

행동:
수업을 따라가면서 막히는 부분이 생기면 강사님에게 질문하고, AI를 활용해서 부족한 부분을 추가로 학습했다.

결과:
배운 내용을 이해하고 과제를 성공적으로 수행했다.

이 경험에서 드러나는 강점:

- 새로운 분야를 배울 때 모르는 것을 그냥 넘어가지 않는다.
- 필요한 도움을 적극적으로 찾아 학습한다.
- 배운 내용을 실제 과제 수행으로 연결한다.

---

### 경험 2 — AI를 활용해 이해도를 스스로 검증한 경험

상황:
학원에서 새로운 내용을 학습했다.

행동:
배운 내용을 AI에게 비슷한 비유나 다른 방식으로 설명해 달라고 요청하고, 내가 제대로 이해하고 있는지 교차검증했다.

결과:
처음에는 애매하게 이해했던 내용도 개념 간의 흐름을 확실하게 잡고 다음 단계로 넘어갈 수 있었다.

이 경험에서 드러나는 강점:

- 단순히 내용을 외우는 것보다 실제로 이해했는지 확인한다.
- 하나의 설명만 받아들이지 않고 다른 관점에서 검증한다.
- AI를 단순한 답변 도구가 아니라 학습 보조 도구로 활용한다.

---

### 경험 3 — 오류의 원인을 분석하고 기록한 경험

상황:
프로그래밍을 공부하면서 오류가 발생하거나 막히는 상황이 있었다.

행동:
단순히 오류를 해결하는 것에서 끝내지 않고, 왜 해당 오류가 발생했는지 원인을 분석하고 그 내용을 메모해두었다.

결과:
비슷한 오류가 다시 발생하는 비중이 크게 줄었고, 비슷한 문제를 겪는 주변 사람들에게 원인과 해결 방향을 조언할 수 있게 되었다.

이 경험에서 드러나는 강점:

- 문제가 생겼을 때 단순히 해결하는 데서 끝내지 않는다.
- 원인을 파악하고 기록해서 같은 문제의 반복을 줄인다.
- 개인적인 학습 경험을 다른 사람에게 도움을 주는 지식으로 연결한다.

---

## 3. 웹페이지의 핵심 메시지

페이지를 방문한 사람이 다음과 같은 인상을 받을 수 있도록 구성해줘.

> "새로운 것을 배울 때 모르는 부분을 적극적으로 찾아보고,
> 제대로 이해했는지 스스로 검증하며,
> 문제가 생기면 원인을 기록해서 다음에는 더 나아지는 사람"

다만 위 문장을 그대로 크게 표시할 필요는 없다.

내 경험을 바탕으로 더 자연스럽고 세련된 한 문장의 핵심 메시지를 만들어서 HERO 영역에 사용해줘.

---

## 4. 페이지 구성

하나의 긴 스크롤 페이지로 만들어줘.

### SECTION 1. HERO

첫 화면에서 나라는 사람의 방향성을 바로 보여준다.

포함할 내용:

- 짧고 인상적인 메인 카피
- 1\~2문장의 자기소개
- 내가 어떤 방식으로 배우고 문제를 해결하는 사람인지 표현
- 아래 경험 섹션으로 이동하는 버튼

너무 거창한 자기소개보다는 신입/학습자의 진솔함이 느껴지는 방향으로 작성해줘.

---

### SECTION 2. ABOUT / 내가 일하고 배우는 방식

내 경험에서 공통적으로 나타나는 특징을 3가지 키워드로 정리해줘.

예시 방향:

1. 적극적으로 질문하고 보완하는 학습
2. 이해한 내용을 스스로 검증하는 습관
3. 문제의 원인을 기록하고 반복을 줄이는 방식

각 키워드는 짧은 설명과 함께 카드 형태로 보여줘.

단순한 성격 소개가 아니라 아래 경험과 자연스럽게 연결되어야 한다.

---

### SECTION 3. EXPERIENCE / 실제로 해본 것

가장 중요한 섹션이다.

3개의 경험을 각각 하나의 카드 또는 독립적인 블록으로 보여줘.

각 경험은 반드시 다음 구조를 사용한다.

**WHEN / WHERE**
언제·어디서 있었는가

**ACTION**
내가 실제로 무엇을 했는가

**RESULT**
어떤 결과가 생겼는가

각 경험에 적절한 제목을 만들어줘.

예를 들어 다음과 같은 형태가 가능하다.

"모르는 것을 그냥 넘기지 않는 학습"

상황 → 행동 → 결과

"제대로 이해했는지 스스로 검증하기"

상황 → 행동 → 결과

"오류를 해결하는 것에서 원인을 기록하는 것으로"

상황 → 행동 → 결과

단, 위 제목을 그대로 사용할 필요는 없으며 경험의 내용을 가장 잘 표현하는 제목으로 다듬어줘.

---

## 5. 공개 가능한 근거

통과 기준은 다음과 같다.

**소개 3개와 공개 가능한 근거 1개가 같은 화면에서 연결되어 보여야 한다.**

따라서 Experience 섹션 또는 그 주변에 다음과 같은 "Evidence" 영역을 만들어줘.

공개 가능한 근거:

- 학원에서 수행한 과제
- 학습하면서 작성한 오류/원인 메모
- 학습 내용을 정리한 기록
- 직접 작성한 학습 자료 또는 코드

단, 실제 링크나 파일을 내가 제공하지 않았으므로 가짜 링크를 만들지 않는다.

대신 다음과 같이 표시할 수 있는 영역을 만들어줘.

`공개 가능한 학습 기록 / 과제 / 메모를 추가할 수 있는 영역`

그리고 HTML 코드 안에서 나중에 내가 실제 링크를 넣을 수 있도록 주석으로 위치를 표시해줘.

예:
`<!-- 나중에 실제 공개 가능한 학습 기록 링크를 여기에 추가 -->`

---

## 6. 디자인 방향

전체적인 느낌은 다음과 같다.

- 깔끔하고 현대적인 개인 포트폴리오
- 개발자/IT 학습자의 느낌
- 너무 기업 홈페이지처럼 딱딱하지 않게
- 너무 화려한 효과를 사용하지 않기
- 콘텐츠가 가장 잘 읽히는 디자인
- 충분한 여백
- 카드와 섹션을 활용한 명확한 정보 구조
- 신뢰감 있고 차분한 분위기

색상은 흰색 또는 아주 옅은 회색을 기본 배경으로 하고,
짙은 네이비/블랙 계열을 메인 컬러,
하나의 포인트 컬러를 사용해줘.

타이포그래피는 가독성을 최우선으로 한다.

## 7. 인터랙션

JavaScript는 꼭 필요한 정도만 사용한다.

가능하다면 다음 정도의 간단한 인터랙션을 넣어줘.

- 상단 네비게이션 클릭 시 해당 섹션으로 부드럽게 이동
- Experience 카드에 마우스를 올렸을 때 자연스러운 hover 효과
- 스크롤에 따른 아주 간단한 등장 애니메이션

과도한 애니메이션이나 복잡한 기능은 넣지 않는다.

---

## 8. 반응형

PC와 모바일 모두에서 보기 좋도록 만들어줘.

특히 모바일에서는:

- 카드가 세로로 자연스럽게 배치되고
- 글자가 너무 작아지지 않으며
- 여백이 적절하고
- 가로 스크롤이 발생하지 않도록 해줘.

---

## 9. HTML 파일 조건

최종 결과물은 **단 하나의 HTML 파일**이어야 한다.

다음 조건을 반드시 지켜줘.

- `<!DOCTYPE html>`부터 시작
- HTML + CSS + JavaScript를 하나의 파일에 모두 포함
- 별도의 CSS 파일을 만들지 않는다.
- 별도의 JS 파일을 만들지 않는다.
- 빌드 도구가 필요하지 않도록 한다.
- 브라우저에서 `.html` 파일을 바로 열었을 때 정상적으로 작동해야 한다.
- 외부 라이브러리는 가능하면 사용하지 않는다.
- 이미지가 필요하다면 실제 이미지 파일이 없는 상태에서도 레이아웃이 깨지지 않도록 구성한다.
- 실제 존재하지 않는 이미지, 링크, 경력 등을 만들어내지 않는다.

---

## 10. 최종 출력

설명은 최소화하고 **바로 저장해서 사용할 수 있는 완성된 HTML 코드 전체**를 출력해줘.

코드 내부에는 내가 나중에 직접 수정하기 쉽도록 주요 영역마다 간단한 주석을 넣어줘.

특히 다음 부분은 나중에 수정하기 쉽게 표시해줘.

- 이름
- 자기소개
- 경험 3개
- 공개 가능한 근거 링크
- 이메일/연락처
- GitHub 또는 기타 링크

마지막으로 코드를 작성하기 전에 내가 제공한 경험에서 공통적으로 드러나는 강점을 먼저 정리하고, 그 강점이 페이지의 디자인과 문구에 자연스럽게 반영되도록 해줘.

**중요: 내가 제공한 경험 이상의 경력이나 성과를 절대 만들어내지 마.**
