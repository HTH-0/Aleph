ZFW란?
	>> 내부에서 나간 트래픽 허용, 내부에서 나갔던 트래픽 돌아오는 것 허용
	>> 하지만 외부에서 먼저 들어오는 트래픽 차단

R2(config)#zone security inside

R2(config)#zone security outside
	>R2에 내부신뢰망, 외부 비신뢰망 선언

R2(config)#in fa0/0
R2(config-if)#zone-member security inside

R2(config)#in fa0/1
R2(config-if)#zone-member security outside
	> 각 인터페이스에 zone 할당
	> FW에서는 인터페이스가 특정 보안 존에 소속되는 순간, 서로 다른 존 간의 모든 트래픽이 기본적으로 전면 차단(Default Deny)

R2#show zone security

R4#ping 10.10.10.1
	>> 안됨
R4#ping 20.20.20.3
	>> 통신 됨

R2(config)#zone-pair security inout source inside destination outside
	>> zone pair 선언 >> 출발지를 inside, 목적지를 outside 설정 : 통로 이름표 설정

R2(config)#ip access-list extended acltest

R2(config-ext-nacl)#permit ip any any
	>> 트래픽 정의를 위한 ACL 작성 : 모든 트래픽을 감시하게 한다

R2(config)#class-map type inspect classtest
	>> 방화벽 검사(type inspect) 용도의 classtest라는 클래스 맵을 만들기

R2(config-cmap)#match access-group name acltest
	>>  acltest ACL 조건에 맞는 트래픽을 이 클래스로 묶기
	>> Inside에서 Outside로 향하는 모든 IP 트래픽이 classtest라는 그룹으로 분류

R2(config)#policy-map type inspect policytest
	>> Policy-map (정책모음) 만들기

R2(config-pmap)#class type inspect classtest
	>> 클래스 지정

R2(config-pmap-c)#inspect
	>> 해당 클래스에 상태기반검사 지정

R2(config-sec-zone-pair)#service-policy type inspect policytest
	>> 정책 최종 바인딩

R2#show class-map

R2#show class-map type inspect

R2#show policy-map type inspect
