# 브라우저 기반 닷지 피하기 미니게임 개발 요청

브라우저에서 바로 실행할 수 있는 **2D 닷지 피하기(Dodge) 미니게임**을 만들어줘.

게임의 핵심은 플레이어가 키보드로 캐릭터를 움직여 화면에 등장하는 장애물(탄막)을 피하면서 최대한 오래 생존하는 것이다.

단순한 기능 구현이 아니라 **실제로 플레이했을 때 조작감이 좋고, 게임다운 UI/UX와 피드백을 갖춘 완성도 있는 미니게임**을 목표로 한다.

---

## 1. 기본 개발 환경

다음 기술을 사용해서 만들어줘.

* HTML5
* CSS3
* JavaScript
* Canvas API

별도의 서버 없이 브라우저에서 HTML 파일을 실행하면 바로 플레이할 수 있도록 구성한다.

가능하면 다음과 같이 파일을 분리해서 작성한다.

```text
index.html
style.css
js/
 ├─ game.js
 ├─ player.js
 ├─ obstacle.js
 ├─ input.js
 └─ ui.js
```

단, 너무 과도하게 파일을 분리하지 말고 각 파일의 역할이 명확하도록 모듈화한다.

외부 라이브러리는 사용하지 않는다.

---

# 2. 게임 기본 규칙

게임 장르는 **닷지 피하기**이다.

플레이어는 화면 안에서 자유롭게 이동하면서 장애물을 피한다.

### 승리/패배 조건

이번 버전의 기본 승리 조건은 다음과 같이 설정한다.

* 목표 생존 시간: **30초**
* 플레이어 목숨: **1개**
* 장애물과 플레이어의 Hitbox가 충돌하면 즉시 Game Over
* 30초 동안 생존하면 게임 클리어

게임 시작 후 시간이 흐를수록 점수가 증가한다.

예:

```text
생존 시간 1초 = 100점
생존 시간 10초 = 1000점
생존 시간 30초 = 3000점
```

점수는 반드시 실제 생존 시간을 기반으로 계산되도록 한다.

---

# 3. 플레이어

플레이어는 화면 안에서 키보드로 이동한다.

### 조작

```text
↑ : 위
↓ : 아래
← : 왼쪽
→ : 오른쪽
```

추가로 가능하다면

```text
W : 위
A : 왼쪽
S : 아래
D : 오른쪽
```

도 지원한다.

### 플레이어 속성

다음 값을 하나의 설정 객체 또는 상수로 관리한다.

```javascript
player = {
    x,
    y,
    speed,
    size,
    hitboxRadius
}
```

기본값은 적절하게 설정하되 쉽게 수정할 수 있도록 한다.

예:

```text
이동 속도: 300px/s
캐릭터 크기: 30px
Hitbox: 캐릭터 내부의 작은 원
```

---

# 4. 플레이어 Hitbox

게임의 중요한 요소다.

캐릭터 이미지 전체가 충돌 영역이 되어서는 안 된다.

플레이어 캐릭터 안쪽에 **작은 원형 Hitbox**를 만든다.

개념적으로:

```text
┌─────────────┐
│   캐릭터     │
│     ●       │ ← 실제 Hitbox
│             │
└─────────────┘
```

캐릭터 그래픽이 장애물과 살짝 닿는 정도는 허용한다.

하지만 실제 원형 Hitbox가 장애물의 Hitbox와 충돌하면 즉시 피격 처리한다.

### Hitbox 시각화

개발 및 게임 플레이 중 Hitbox가 명확하게 보이도록 한다.

예:

* 작은 원형 테두리
* 또는 은은하게 빛나는 원
* 플레이어 중심에 배치

Hitbox의 크기를 쉽게 변경할 수 있도록 코드의 설정값으로 분리한다.

---

# 5. 장애물 / 탄막

장애물은 화면 외부 또는 지정된 Spawn Point에서 생성되어 화면 안으로 들어온다.

장애물에는 다음과 같은 속성을 가진다.

```javascript
obstacle = {
    x,
    y,
    radius,
    speed,
    angle,
    type
}
```

### 기본 장애물

첫 번째 기본 패턴은 **직선형 장애물**이다.

예:

```text
●
 ↓
 ↓
 ↓

플레이어 → ○
```

화면 위쪽에서 생성되어 아래쪽으로 이동하거나 화면 바깥에서 다양한 방향으로 진입하도록 한다.

---

# 6. 장애물 생성 주기

난이도를 조절하는 핵심 변수는 **단 하나의 변수**를 중심으로 설계한다.

핵심 난이도 변수:

```javascript
spawnInterval
```

예:

```text
초반: 0.8초
중반: 0.5초
후반: 0.3초
```

단, 여러 개의 난이도 변수를 무작정 동시에 증가시키지 않는다.

기본 난이도 조절은 `spawnInterval`을 중심으로 한다.

즉,

```text
spawnInterval 감소
        ↓
장애물 생성 빈도 증가
        ↓
난이도 상승
```

구조로 만든다.

장애물의 속도나 패턴은 점수 구간에 따라 제한적으로 추가할 수 있지만, 전체 난이도 시스템의 중심은 `spawnInterval` 하나로 유지한다.

---

# 7. 장애물 패턴 다양화

게임 초반에는 기본 직선형 장애물만 등장한다.

시간/점수가 증가하면 새로운 패턴이 등장한다.

## 패턴 1 - 직선형

기본적인 탄막.

```text
↓
↓
↓
↓
```

플레이어를 직접 추적하지 않고 일정한 방향으로 이동한다.

---

## 패턴 2 - 유도형(Homing)

플레이어의 현재 위치를 기준으로 방향을 계산하여 플레이어 쪽으로 이동하는 장애물.

단, 너무 강력하면 피할 수 없으므로 적절한 속도 제한을 둔다.

예:

```javascript
direction = normalize(player.position - obstacle.position)
```

장애물이 생성되는 순간 플레이어를 향하도록 하거나, 약한 추적 기능을 적용한다.

플레이어를 완벽하게 추적해서 피할 수 없는 상황은 만들지 않는다.

---

## 패턴 3 - 패턴형

불규칙하거나 곡선 형태로 움직이는 장애물.

예:

* 좌우로 흔들리며 이동
* Sin/Cos 기반 곡선 이동
* 대각선 이동
* 일정한 각도로 회전하며 이동

처음부터 모든 패턴을 넣지 말고 기본 직선형 → 유도형 → 패턴형 순으로 확장한다.

---

# 8. 난이도 상승

게임 시간이 흐를수록 자연스럽게 난이도가 올라가야 한다.

예:

### 0~10초

```text
직선형 장애물
spawnInterval = 0.8초
```

### 10~20초

```text
직선형 + 일부 패턴형
spawnInterval = 0.6초
```

### 20~30초

```text
직선형 + 유도형 + 패턴형
spawnInterval = 0.4초
```

위 숫자는 예시이므로 실제 게임 플레이 테스트 후 조절한다.

중요한 것은 **처음부터 너무 어렵지 않고 점점 긴장감이 증가하는 구조**다.

---

# 9. 점수 시스템

시간이 흐를수록 점수가 증가한다.

기본 점수:

```text
1초 생존 = 100점
```

따라서

```text
5초 = 500점
10초 = 1000점
20초 = 2000점
30초 = 3000점
```

점수는 화면에 실시간으로 표시한다.

예:

```text
SCORE
1,500
```

---

# 10. 점수 기반 새로운 패턴 등장

특정 점수에 도달하면 새로운 장애물 패턴을 해금한다.

예:

```text
0점
↓
기본 직선형

1000점
↓
새로운 패턴 추가

2000점
↓
유도형 등장

3000점
↓
최종 난이도
```

이 구조를 코드에서도 명확하게 관리한다.

예:

```javascript
if (score >= 2000) {
    // Homing obstacle unlocked
}
```

단, 같은 조건을 매 프레임마다 불필요하게 처리하지 않도록 구조적으로 관리한다.

---

# 11. 게임 상태 관리

게임은 다음 상태를 가진다.

```text
START
  ↓
PLAYING
  ↓
GAME OVER
  ↓
RESTART
  ↓
PLAYING
```

### START

게임 시작 전 화면.

표시:

```text
DODGE

30초 동안 살아남으세요!

[게임 시작]
```

---

### PLAYING

실제 게임이 진행되는 상태.

표시:

```text
SCORE: 1200
TIME: 12.0s
```

---

### GAME OVER

플레이어가 장애물에 맞았을 때 표시.

예:

```text
GAME OVER

SCORE
1,750

SURVIVAL TIME
17.5s

[다시 시작]
```

---

### CLEAR

30초 생존에 성공했을 경우.

예:

```text
CLEAR!

30초 생존 성공!

SCORE
3,000

[다시 플레이]
```

가능하다면 Game Over와 Clear 화면을 시각적으로 구분한다.

---

# 12. 게임 루프

Canvas 기반의 `requestAnimationFrame()`을 사용한다.

기본적인 구조는 다음과 같다.

```javascript
requestAnimationFrame(gameLoop);
```

게임 루프에서는 다음을 처리한다.

```text
1. 입력 처리
2. 플레이어 이동
3. 장애물 생성
4. 장애물 이동
5. 충돌 검사
6. 점수 계산
7. 난이도 업데이트
8. 화면 렌더링
9. UI 업데이트
```

시간 기반 이동을 사용하여 프레임 속도에 따라 게임 속도가 달라지지 않도록 한다.

즉,

```javascript
position += velocity * deltaTime;
```

형태로 구현한다.

---

# 13. 플레이어 조작감

플레이어 이동은 매우 중요하다.

키보드 입력에 즉각적으로 반응하면서도 부드럽게 움직여야 한다.

다음 사항을 지켜라.

* 키를 누르고 있는 동안 지속적으로 이동
* 키를 떼면 즉시 또는 매우 빠르게 이동 정지
* 대각선 이동 시 지나치게 빠른 속도가 되지 않도록 정규화
* 화면 밖으로 나가지 못하도록 경계 처리
* `deltaTime` 기반 이동

예:

```text
↑ + →
```

를 동시에 누르면 대각선 이동이 가능해야 한다.

---

# 14. 충돌 판정

플레이어와 장애물의 충돌은 원형 Hitbox 기준으로 처리한다.

예:

```javascript
distance(player, obstacle)
    < player.hitboxRadius + obstacle.radius
```

이면 충돌이다.

충돌 판정은 시각적인 캐릭터 크기보다 작은 Hitbox를 기준으로 한다.

즉, 플레이어에게 어느 정도 여유가 있어야 한다.

---

# 15. UX / 화면 레이아웃

게임 화면은 직관적이어야 한다.

권장 레이아웃:

```text
┌─────────────────────────────────────┐
│ SCORE: 1200             TIME: 12.5s │
│                                     │
│                                     │
│             ●                       │
│                                     │
│       ○                             │
│                         ○           │
│                                     │
│                  PLAYER             │
│                                     │
│                                     │
└─────────────────────────────────────┘
```

### UI 위치

상단:

* 점수: 좌측
* 남은 시간 또는 생존 시간: 우측

게임 시작 전:

* 중앙에 게임 제목
* 게임 설명
* 시작 버튼

게임 종료:

* 중앙에 결과
* 최종 점수
* 생존 시간
* 재시작 버튼

---

# 16. 반응형 화면

데스크톱 브라우저에서 플레이하는 것을 우선한다.

Canvas는 브라우저 크기에 맞춰 적절하게 표시되도록 한다.

가능하다면 다음도 고려한다.

* 화면 크기 변경 대응
* Canvas 내부 좌표와 실제 CSS 크기 분리
* 너무 작은 화면에서는 적절한 안내 표시

게임이 화면을 벗어나거나 UI가 깨지지 않도록 한다.

---

# 17. 시각적 디자인

단순한 사각형만 나열하는 테스트 프로그램처럼 보이지 않도록 한다.

다음 요소를 활용한다.

### 플레이어

간단한 캐릭터 또는 아이콘 형태.

예:

```text
작은 우주선
원형 캐릭터
빛나는 코어
```

단, 외부 이미지 파일 없이 Canvas로 직접 그릴 수 있는 형태를 우선한다.

### 장애물

탄막처럼 보이는 디자인.

예:

* 원형 탄환
* 빛나는 구체
* 삼각형
* 작은 에너지 볼

장애물마다 색상이나 모양으로 패턴을 구분할 수 있게 한다.

---

# 18. 피드백 / 이펙트

게임의 몰입감을 높이기 위해 최소한의 피드백을 구현한다.

### 충돌 시

다음 중 가능한 것을 구현한다.

* 화면 흔들림(Screen Shake)
* 플레이어 깜빡임
* 파티클 효과
* 장애물 파괴 효과
* 피격 사운드

외부 사운드 파일을 사용하지 않아도 된다.

가능하다면 Web Audio API를 이용해 간단한 효과음을 생성한다.

---

# 19. 파티클 효과

충돌 또는 게임 종료 시 간단한 파티클 효과를 보여준다.

예:

```text
     *
  *  ●  *
     *
 *     *
```

너무 복잡하게 구현할 필요는 없지만, 충돌 순간에 시각적인 피드백이 느껴지도록 한다.

---

# 20. 게임 시작 / 재시작

게임 시작 버튼을 누르면 게임이 초기화되고 시작된다.

재시작 시 다음 데이터를 모두 초기화한다.

```text
플레이어 위치
장애물 배열
점수
생존 시간
게임 상태
난이도
spawnTimer
파티클
Screen Shake
```

이전 게임의 장애물이 남아 있거나 점수가 이어지는 문제가 없어야 한다.

---

# 21. 코드 구조

코드는 기능별로 모듈화한다.

권장 구조:

```text
Game
 ├─ Game State
 ├─ Game Loop
 ├─ Player
 │   ├─ Input
 │   ├─ Movement
 │   └─ Hitbox
 │
 ├─ Obstacles
 │   ├─ Spawn
 │   ├─ Movement
 │   ├─ Pattern
 │   └─ Collision
 │
 ├─ Difficulty
 │
 ├─ Score
 │
 ├─ Particle
 │
 └─ UI
```

각 기능이 서로 강하게 얽히지 않도록 한다.

특히 다음 값들은 상단의 설정 객체에서 쉽게 수정할 수 있게 한다.

```javascript
GAME_CONFIG
PLAYER_CONFIG
OBSTACLE_CONFIG
DIFFICULTY_CONFIG
```

# 22. 개발 순서

한 번에 모든 기능을 구현하지 말고 다음 순서로 개발한다.

## STEP 1

플레이어 이동 구현

* Canvas 생성
* 플레이어 생성
* WASD / 방향키 입력
* 부드러운 이동
* 화면 경계
* Hitbox 표시

먼저 이 단계가 정상적으로 작동하는 코드를 완성한다.

---

## STEP 2

장애물 구현

* 장애물 생성
* spawnInterval 적용

# 23. 중요한 개발 원칙

다음 사항을 반드시 지켜라.

### 1. 실제로 실행 가능한 코드

코드 일부만 작성하지 말고 최종적으로 브라우저에서 실행 가능한 형태로 완성한다.

### 2. 복사해서 바로 실행 가능

필요한 파일과 전체 코드를 제공한다.

사용자가 파일을 저장한 뒤 `index.html`을 브라우저에서 실행하면 게임이 작동해야 한다.

### 3. 오류 없는 구조

JavaScript 콘솔에 오류가 발생하지 않도록 한다.

### 4. 기능 우선 개발

화려한 디자인보다 다음 기능이 먼저 제대로 작동해야 한다.

```text
이동
→ 장애물
→ 충돌
→ 점수
→ 게임 종료
→ 재시작
```

### 5. 지나치게 어려운 게임이 되지 않도록 한다

플레이어가 장애물을 보고 피할 수 있는 충분한 시간이 있어야 한다.

유도형 장애물도 피할 수 있도록 속도와 생성 위치를 조절한다.

### 6. Hitbox는 관대하게

캐릭터 외형보다 실제 Hitbox를 작게 만들어 플레이어가 컨트롤하기 편하게 한다.

### 7. 수정하기 쉬운 코드

게임 밸런스를 수정할 때 여러 파일을 찾아다니지 않도록 설정값을 한곳에 모은다.

# 25. AI의 답변 방식

개발을 시작할 때 한 번에 모든 코드를 설명만 하지 말고 **실제로 사용할 수 있는 코드 중심으로 진행한다.**

먼저 STEP 1부터 구현한다.

각 단계마다 다음 형식으로 답변한다.

```text
[현재 단계]
STEP 1 - 플레이어 이동

[구현 내용]
무엇을 구현했는지 간단히 설명

[파일 구조]

[전체 코드]

[실행 방법]

[테스트 방법]

[다음 단계]
```

각 단계의 코드가 실제로 실행 가능한지 확인한 뒤 다음 단계로 넘어간다.

최종 단계에서는 모든 기능이 통합된 **완성본 전체 코드**를 제공한다.

## 최종 목표

최종 결과물은 단순한 코딩 예제가 아니라,

**"30초 동안 탄막을 피하면서 최대한 높은 점수를 얻는 브라우저 미니게임"**

으로 느껴져야 한다.

게임을 처음 실행했을 때 사용자가 별도의 설명 없이도

```text
게임 시작
↓
이동
↓
장애물 회피
↓
점수 상승
↓
난이도 증가
↓
30초 생존 또는 피격
↓
결과 확인
↓
재시작
```

의 흐름을 자연스럽게 이해할 수 있도록 만들어라.

특히 **조작감, 충돌 판정의 공정성, 난이도 상승의 자연스러움, UI의 직관성**을 가장 중요하게 고려해라.
